# Sessions

## 2026-10-23 — M0 Foundation

### Built

- Expo SDK 58 (`expo@~58.0.17`, React Native 0.88, React 19.3) from the `default@sdk-58` template; demo screens, components, web files and unused assets removed. Routes in `app/` per SPEC §3. `tsconfig`: `strict`, `noUncheckedIndexedAccess`.
- `app.config.ts`: name Aulos, slug/scheme `aulos`, package `com.anywecon.aulos`, `userInterfaceStyle: automatic`, Android only. Plugins: expo-router, expo-splash-screen, expo-sqlite (`enableFTS: true`), expo-audio (`enableBackgroundPlayback: true`, `recordAudioAndroid: false`, `microphonePermission: false`), plus an inline config plugin that adds `READ_EXTERNAL_STORAGE` with `maxSdkVersion="32"`.
- `src/db`: `Db` interface; expo-sqlite implementation (WAL, `foreign_keys = ON`, exclusive transactions, FTS5 check that fails startup instead of falling back); better-sqlite3 implementation for Jest (`test/node-db.ts`); forward-only migration runner; migration 001 (all SPEC §6 tables, `albums`/`artists` views, `tracks_fts` FTS5 external-content table with insert/update/delete triggers, unique index on `(provider, provider_ref)`); JSON `kv` helpers.
- `modules/media-store`: local Expo module (Android/Kotlin). `queryAudio()` is a coroutine `AsyncFunction` on `Dispatchers.IO` over `MediaStore.Audio.Media.EXTERNAL_CONTENT_URI` where `IS_MUSIC != 0`; returns id, contentUri, title, artist, album, albumArtist (null below API 30), trackNo/discNo (split from `TRACK`), durationMs, sizeBytes, dateModified (ms), albumId, mimeType. MediaStore's `<unknown>` placeholder maps to null. Typed TS wrapper.
- `src/library`: permission helpers (READ_MEDIA_AUDIO on API 33+, READ_EXTERNAL_STORAGE below); pure `diffLocalTracks` / `toTrackFields`; `scanLibrary` applies the diff in one transaction and returns `{ added, updated, removed, total, durationMs }`.
- Zustand stores: `settings` (theme `system | light | dark`, persisted in `kv`), `library` (permission, scan status, error, track count, last scan persisted in `kv`).
- i18n: i18next + react-i18next, single typed English resource `src/i18n/en.ts`; every UI string goes through `t()`.
- UI: native tabs. Library (asks for access on first start, scans once, Scan button, track count, last scan time, added/updated/removed, denied/blocked/empty/error states, re-reads permission on resume). Settings (theme, version, licence). Light and dark palettes; the theme setting overrides the system scheme via `Appearance.setColorScheme`.
- Tooling: ESLint (`eslint-config-expo/flat` + Prettier), Jest (`jest-expo`) + React Native Testing Library, scripts `typecheck`, `lint`, `test`, `format`, `android:prebuild`, `android:release`. CI in `.github/workflows/ci.yml`. Maestro flow `.maestro/m0-launch.yaml`.
- Docs: LICENSE (GPL-3.0 text, sha256 `3972dc97…6986`), README, CLAUDE.md, this file.

### Deviations and notes

- `create-expo-module --local` hung at "Creating the module from template files" on this machine (also with `--source` pointing at a manually fetched `expo-module-template@58.0.8` and telemetry off). The module was written by hand from that same template (`expo-module.config.json`, `android/build.gradle`, `AndroidManifest.xml`, Kotlin module, `src/*.ts`), Android only.
- `react-dom` is kept as a dependency: expo-router's Radix peers otherwise pull `react-dom@19.3.1`, which conflicts with the pinned `react@19.3.0`.
- `expo-symbols` is kept: native tab icons use Material Symbols (`md`), which expo-router resolves through it.
- `INTERNET` is blocked in M0 (no network calls); unblock it in M2 when providers arrive.
- FTS5 `unicode61 remove_diacritics 2` folds case (including Greek) and Latin diacritics, but not Greek tonos: `χατζιδακις` does not match `Χατζιδάκις`. M1 search needs an accent-folded search column or query-side normalisation.
- The M0 release APK is signed with the debug keystore generated by prebuild. The real release keystore arrives in M4 and never goes in the repo.

## 2026-10-24 — M1 Offline player

### Built

- **Search normalisation.** `normalizeText` (`src/search/normalize.ts`): NFD, strip every `\p{M}`, lowercase, `ς` → `σ`, collapse whitespace; the same function writes the columns and builds queries. Migration 002 adds `title_norm`, `artist_norm`, `album_norm`, `album_artist_norm` (plus `year` and `added_at` for sorting), backfills them in TypeScript, rebuilds `tracks_fts` over the norm columns with new triggers (created after the backfill, then `rebuild`) and widens the `albums`/`artists` views (sort keys, year, a sample track for artwork). Migrations gained an optional `up(tx)` data step that runs in the same transaction. Queries use FTS5 prefix matching per token (`"χατζ"* "μαν"*`); albums, artists and playlists match every token as a substring of the normalised name.
- **Library browse.** Library tab: status card (M0 test IDs kept), section chips Songs · Albums · Artists · Playlists · Favorites · Recent, Songs sorted by title/artist/date added, Albums by name/artist/year (year offered only when tags exist), album detail in disc/track order, artist detail (albums, then all tracks). All lists are FlashList v2; rows have a ⋮ menu (play next, add to queue, add to playlist, favorite, go to album/artist) and long-press multi-select (play next / add to queue / add to playlist).
- **media-store module.** `queryAudio` now returns year, date added and the volume-relative folder (`RELATIVE_PATH` on API 29+, parent of `DATA` below). `getVersion()` returns MediaStore version + per-volume generation on API 30+, or music count + newest `DATE_MODIFIED` below; the library rescans on start and on resume only when that token changed. `loadArtwork(contentUri, sizePx)`: `loadThumbnail` on API 29+, the album-art URI below, JPEG in `cacheDir/artwork/<albumId>_<size>.jpg`, a `.none` marker for albums without art, on `Dispatchers.IO`, returns `file://` or null. `checkFiles(uris)`: opens each URI and hands missing files to the media scanner. TS side: an LRU in front of it (`src/library/artwork.ts`, shared in-flight requests, size buckets, failures not cached; unit-tested).
- **Album grouping (migration 003).** Each track stores `album_ref` (MediaStore `ALBUM_ID` for local tracks) and `album_key` (`albumGroupKey`, `src/library/albumKey.ts`): album artist + album (normalised) when the album artist tag is present; otherwise the MediaStore album id for provider `local`, falling back to album + folder; non-local tracks without album artist use album + the provider's album ref. The `albums` view groups by the key and shows the album artist, or for albums without one the most frequent track artist when it holds at least half of the tracks, otherwise "Various Artists". Albums are addressed by key in routes, favorites and the artwork cache. The migration keys existing rows, converts legacy `[name, artist]` album favorites, and clears `library.mediaVersion` so the next start rescans and backfills `album_ref`; a rescan that re-keys an album moves its favorite to the new key. Unit tests: featured-artist album stays one album, same-named albums in different folders stay two, Various Artists, re-run of 003 is a no-op, rescan backfill keeps favorites. `test-media.ps1` adds "Featuring Tape" (4 tracks: "Aulos Crew" ×2, "… feat. Δέλτα", "… feat. Echo", no album artist), asserted in `m1-browse` as one album "Aulos Crew · 2026 · 4 tracks". The `albums` view lists 2,000 albums of 20,000 tracks in 30 ms (Node, better-sqlite3).
- **Library folders.** Settings → Library folders lists distinct folders with counts; switching one off excludes it and its subfolders (kept in `kv` `library.excludedFolders`), applied by one rescan when leaving the screen.
- **Player.** `src/player/PlayerService.ts` is the only `expo-audio` importer (ESLint `no-restricted-imports`). The native `AudioPlaylist` holds a window of the queue (4 behind, 8 ahead) instead of the whole queue; every queue change is planned as a few `insert`/`remove`/`skipTo` calls (`src/player/window.ts`, property-tested over 500 random edits) that never remove the playing item. Queue model (`src/player/queue.ts`): play now/next, add, remove, move, clear, shuffle with the original order kept for unshuffle, repeat off/all/one (one = native `single` loop), previous restarts after 3 s. Persistence: track ids, index, position, repeat and shuffle order in `kv` `player.queue`, saved at most every 5 s while playing, on pause, on track change and on background; restored paused at the saved position. Background: `setAudioModeAsync({ shouldPlayInBackground: true, interruptionMode: 'doNotMix' })`, `setActiveForLockScreen` on first play with title/artist/album/artwork (512 px `file://` thumbnail), metadata updated on every track change. Headphone disconnect: expo-audio builds its ExoPlayer with `setHandleAudioBecomingNoisy(true)`, so nothing was added. Missing files: files entering the window are checked first and skipped with a toast; a player error on the current item skips it the same way and rebuilds the native playlist. Sleep timer: 15/30/45/60 min deadline or end of track; checked on every status update and by a 1 s timer, fades over 5 s, then pauses; end of track loads nothing after the current item, so playback stops exactly at its end.
- **Now Playing / mini player / queue.** Mini player above the native tabs and at the bottom of pushed screens. Full-screen Now Playing: artwork, titles, seek bar (community slider), previous/play-pause/next, shuffle, repeat, favorite, sleep timer with remaining time. Queue sheet: tap to jump, × to remove, drag by the handle to reorder.
- **Collections.** Playlists: create, rename, delete with confirmation, add (single or multi-select, or from the picker with "New playlist"), remove, move up/down, drag reorder (`src/ui/ReorderableList.tsx`: RNGH v3 `usePanGesture` + Reanimated shared values, autoscroll at the edges). Favorites for tracks, albums and artists, shown in the Library's Favorites section. History: `PlayCounter` counts a play after 30 s or half the track (listened time = forward position steps while playing, so seeks do not count), once per play; a restart or repeat-one loop is a new play; the final listened time is written when the play ends. "Recent" lists distinct tracks by last play. Export/import: versioned JSON (`format: "aulos.playlist"`, `version: 1`, per track `provider`, `provider_ref`, `title`, `artist`, `album`, `duration_ms`) through the share sheet (expo-sharing) and document picker (expo-document-picker + expo-file-system); import re-matches by `(provider, provider_ref)` — only when the normalised title also agrees, because local refs are per-device MediaStore ids — then by normalised title + artist with duration ±2 s (closest wins); a toast reports matched/unmatched counts.
- **Search tab.** Debounced 150 ms, grouped Songs / Albums / Artists / Playlists, hint and no-results states, refreshes after rescans and playlist edits.
- **Release build.** `expo-build-properties`: `enableMinifyInReleaseBuilds`, `enableShrinkResourcesInReleaseBuilds`, and `extraProguardRules` keeping `com.anywecon.aulos.mediastore.**`; every other module ships its own consumer rules (the R8 build passes every flow on both devices).
- **Test tooling.** `scripts/test-media.ps1 -Mode standard|bulk|clean` (ffmpeg fixtures through FFMETADATA files so Greek tags never touch the command line; `adb push`; `content call … scan_volume` rescan on API 30+, per-file scan broadcast below; prints MediaStore counts). `scripts/soak-playback.ps1` (Maestro start or `-Resume` by media key, screen off, `dumpsys media_session` every 5 min, fails on non-PLAYING or a stalled position). `scripts/soak-start.yaml`, `scripts/sleep-timer-start.yaml` (manual-check helpers outside the suite). Maestro flows: `m1-browse`, `m1-playback`, `m1-playlists`, `m1-favorites`, `m1-search-greek`, `m1-permission-denied`, `m1-light-theme`, with `common/fresh-start.yaml` and `common/open-section.yaml`.
- **Album merge for per-track album artist tags (migration 004, view only).** Some downloaders write the featured artists into each track's album artist tag, so one album arrives as several album artists with several MediaStore album ids ("Street Tape 3": 12 tracks, 7 album artists). `albumGroupKeys` (`src/library/albumKey.ts`) runs over the whole scan: local tracks that share the normalised album name and the folder but carry different album artist values become one album keyed `["folder", album, folder]`, unless two of them share a (disc, track) pair (untagged disc counts as 1; tracks without a track number never block the merge); otherwise `albumGroupKey` applies as before. No new columns: the keys are recomputed on every scan. Migration 004 only recreates the `albums` view so the album artist is shown only when every track has the same one, and a merged album uses the most frequent track artist / "Various Artists" rule; it also clears `library.mediaVersion` so the next start rescans and re-keys. Unit tests: "Street Tape 3"-style album becomes one album ("Grey Falcon", 6 of 12), Various Artists for a merged album without a half-majority artist, two "Greatest Hits" with colliding track numbers in one flat folder stay two, same track number on another disc merges, null track numbers merge, single album artist and non-local tracks unchanged; migration 004 leaves `tracks` untouched, clears the media version and is a no-op when re-run. `test-media.ps1` adds "Guest List" (per-track album artists "Aulos Host", "Aulos Host, Δέλτα", "Aulos Host", "Aulos Host, Echo", tracks 1-4) and two "Greatest Hits" (album artists "Aulos Red" and "Aulos Blue", tracks 1-2 each) in one folder; `m1-browse` asserts "Guest List" as one album "Aulos Host · 2026 · 4 tracks" and both "Greatest Hits" rows.
- **Soak screen state.** `soak-playback.ps1` reads `mWakefulness` from `dumpsys power` with every sample, prints it, fails the run if it is ever `Awake`, and refuses to start while Developer options → Stay awake (`stay_on_while_plugged_in`) is on.

### Structure changes and deviations

- Routes moved into `app/(tabs)/` (Library, Search, Settings on NativeTabs) under a root `Stack`, so album, artist, playlist, queue and Now Playing push over the tabs. The M0 Library card moved into `src/ui/LibraryStatus.tsx` and the start/resume logic into `useLibraryLifecycle` (root layout), so rescans on resume happen whichever tab is open. The M0 screen test now renders that card with the lifecycle.
- Mini player "above the tabs": NativeTabs has no bottom accessory on Android, so each tab screen renders the mini player at the bottom of its content, which sits directly above the native tab bar.
- Native window instead of mirroring the whole queue: expo-audio has no batch or move API and every `add`/`remove` is a blocking call that emits a status event, so shuffling a 2,000-track queue would take thousands of calls.
- Drag reorder: re-rendering the list while a pan is active makes RNGH v3 cancel the gesture (seen on the S23), so the drag controller is created once and the floating row lives in its own overlay component.
- Section chips wrap onto two lines instead of scrolling sideways, so every section stays reachable.
- Maestro's `inputText` is ASCII-only on Android; `m1-search-greek` enters "χατζιδακις" with `setClipboard` + `pasteText`.
- The SDK 58 template already sets `android.enableMinifyInReleaseBuilds=true`; the "before" size below is a build with both R8 options overridden to false on the Gradle command line.
- Toasts (missing-file skip) are not visible to Maestro; the message is covered by the player-store unit test.
- `POST_NOTIFICATIONS` stays declared and is never requested: on the S23 the media notification and the lock-screen player appear with the permission not granted (see checklist), so no runtime request was added.

## 2026-10-24/25 — M2 Sources and downloads

### Built

- **Networking (`src/net`).** `createHttpJson`: per-attempt timeout (15 s) combined with caller cancellation, three attempts with full-jitter exponential backoff (500 ms base, 8 s cap) on network errors, 429 (Retry-After as seconds or HTTP date, waited out up to 30 s, reported at once beyond) and 5xx; zod (v4) validation of the body; typed errors `NetworkError`, `RateLimitError`, `NotFoundError`, `InvalidResponseError` that never carry a URL or body (an invalid shape names only the first failing field). The User-Agent is `Aulos/<version> (+<repositoryUrl>)` from `app.config.ts` (`extra.repositoryUrl`) via expo-constants. `http_cache` TTL layer (search 1 h, metadata 24 h, re-validated on read). Connectivity from expo-network (`online`, `unmetered` = Wi-Fi/Ethernet) in a store that also re-reads the state when the app returns to the foreground.
- **Migration 005.** `http_cache`; `tracks.license_url` and `tracks.attribution`; the M0 `downloads` table replaced (nothing ever wrote to it) by the M2 one (`status` queued/downloading/paused/completed/failed, `format`, `file_name` unique, bytes, error code, timestamps); the albums and artists views and the library queries (songs, album/artist tracks, library search) now only show tracks with a file on the device, so the library works offline and streamed-only tracks stay out of it (they still appear in the queue, playlists, favorites and history).
- **Providers (`src/providers`).** `SourceProvider` as in SPEC §4 (`download` receives a destination stem; the provider adds the whitelisted extension of the format it delivers) plus an optional `album(ref)` for the `albums` capability; `ProviderRegistry` with capability lookup and per-provider on/off; `LocalProvider` over the library search, so the Search tab runs one code path; remote tracks are stored in `tracks` on first use (queue, playlist, favourite, download) by `storeTracks`.
- **Internet Archive provider.** `advancedsearch.php` (every word required, Lucene syntax escaped, `mediatype:(audio) AND format:("VBR MP3" OR "MP3")` so every hit has something to stream) and the metadata API, both cached. Items are albums; their audio files (whitelisted extensions: mp3, flac, ogg, oga, opus, wav, aif, aiff, m4a) grouped as original + audio derivatives are tracks; spectrograms, images, playlists, torrents, metadata and archives (one "Flac" item is a RAR) are skipped; tracks without an MP3 are not offered. Title/artist/album/track number/length from the file tags, then the item (a single-track item takes the item title, otherwise the file name); lengths as seconds ("200.28") or clock ("03:20"). `provider_ref` = `identifier/filename`; `license_url` = item `licenseurl`; `attribution` = item `creator`. Remote album key = provider + identifier. Streams the VBR MP3 (then MP3); downloads MP3 (default) or FLAC/Ogg when present, falling back to MP3. Security: identifiers validated (`[A-Za-z0-9][A-Za-z0-9._-]*`), every file-name segment percent-encoded and `.`/`..`/empty segments refused; local download names are a 64-bit FNV-1a hash of provider + ref plus the whitelisted extension, never the remote name. Integrity: the downloaded file's MD5 (`File.digest('MD5')`) is compared with the metadata MD5; a mismatch deletes the file and fails the download. A file larger than what the storage limit still allows is refused before the transfer starts. Search expands only the top 3 items into tracks (1 search + up to 3 metadata requests, then cached).
- **Playback of remote tracks.** The player resolves what to play when an entry enters the native window: a readable file on the device (local or downloaded, checked as before), otherwise the provider's stream (`resolveStream`). A streaming-only track while offline is skipped with "Not available offline: “title”." and the queue continues; a stream that cannot be resolved is skipped like an unplayable file. The queue mixes local, downloaded and streamed tracks. Track info sheet (⋮ → Track info): source, on device / streams, licence (tappable link) and credit. Downloads have no MediaStore artwork, so artwork is only read for `content://` files.
- **Downloads (`src/downloads`).** Pure state machine (queued → downloading → paused → downloading → completed | failed, failed → queued on retry). `DownloadManager`: rows persisted in `downloads`; two transfers at a time; paused ones resume ahead of queued ones; gate = online and (Wi-Fi only off or Wi-Fi/Ethernet); losing the gate pauses running transfers; dropped connections, 5xx and 429 pause and retry after 30 s (or at the next network change), failing after three in a row; transfers that were running when the app stopped become paused at start and resume. Resume uses the SDK 58 `DownloadTask`: a paused task is restored with `DownloadTask.fromSavable` whose Android resume data is the byte offset of the partial file, so the native side sends `Range: bytes=<offset>-` (and starts over if the server ignores it). The storage limit counts completed files plus the expected size of other running/paused downloads. On completion `tracks.local_path`/`file_size` are set in the same transaction. Actions: download a track, a selection, a remote album (album screen) or the remote tracks of a playlist (multi-select); cancel (deletes the partial file), retry, delete one (file removed, the track streams again), delete all. Files live in `Paths.document/downloads/` (app-private, no permission, not in the MediaStore).
- **UI.** Search tab: source chips (Library default; every enabled provider with `search`), debounce 150 ms local / 400 ms remote, cancellation of stale requests, typed error and offline messages. Remote results: play, play next, add to queue, add to playlist, favourite, download, go to album (remote album screen = the album screen with provider/ref), track info. Downloads: Library section and Settings → Downloads (storage used / limit, why queued downloads wait, in progress with bytes, failed with reason and retry, completed tap-to-play, delete one / all). Settings → Sources: provider switches, Wi-Fi only (default on), storage limit (100 MB, 500 MB, 1, 2 (default), 5, 10 GB), download format (MP3 default, FLAC, Ogg).
- **Android.** `INTERNET` allowed; `ACCESS_WIFI_STATE` (brought by expo-network, unused: the connection type comes from `ConnectivityManager`) blocked; `res/xml/network_security_config.xml` with `cleartextTrafficPermitted="false"` and `android:usesCleartextTraffic="false"`; the debug source set overrides the file to allow cleartext only to localhost/127.0.0.1/10.0.2.2 (Metro), release builds never get it.
- **Fixtures.** `scripts/record-fixtures.ps1` records `advancedsearch.php` (same query syntax, fields, rows, page as the app) and metadata responses into `test/fixtures/archive/` (2 searches, 6 items: a Great 78 WAV with FLAC/MP3/Ogg derivatives, a tagged CC BY-SA netlabel album, a RAR-only item, two long single MP3s, a missing item that answers `{}`). Jest answers from these files through `test/archiveFixtures.ts`; no test touches the network.
- **Maestro.** `m2-archive-stream` (tag `network`): search the archive, play "I Gerakina", wait for the position to pass 5 s, check the track info source. `m2-download-offline`: download it, wait for Downloads → completed, `setAirplaneMode: enabled` (Maestro runs `cmd connectivity airplane-mode enable`), play from Downloads until the position passes 3 s, airplane mode off (also in `onFlowComplete`, so a failure never leaves it on).

### INTERNET permission

Needed for the Internet Archive provider: search (`advancedsearch.php`), item metadata (`/metadata/<id>`), streaming and downloads (`/download/<id>/<file>`), all over HTTPS to archive.org. Cleartext traffic stays disabled in release builds (network security config); the LAN question for Nuclear pairing is M3. No analytics or other endpoints; requests carry only the User-Agent.

### Fixes found on the devices

- **Crash (media3 "Invalid PlayerInfo update"):** with repeat all, a queue shorter than the native window (13 entries) was wrapped into it several times; the burst of add/insert/skipTo calls crashed media3's session controller (reproduced on the API 31 emulator in `m1-playback` once the flow played with repeat all). A repeating queue that fits is now loaded once and looped by the native player (`loop: 'all'`); longer queues wrap as before, without duplicates. Unit tests for the window and the store.
- **Downloads stuck after the app returns:** Android blocked the backgrounded app's network (expo-network reported offline) and sent no event when it was unblocked; the network store now re-reads connectivity when the app becomes active.
- **Transient archive.org failures:** one download in the S23 suite ended "Connection failed" (HTTP 5xx); 5xx/429 now pause and retry (three tries) instead of failing at once.
- Maestro: `m1-search-greek` scrolls to the Greek result below the new source switcher; `m1-playback` waits for the queue sheet to close and plays with repeat all, so a slow device cannot miss the playing state of the 6 s queue.

### Download background behaviour (S23, Android 16, release APK, Wi-Fi)

No foreground service is used for downloads (out of scope). Measured with a 134 MB file:

| Situation                                                                      | Result                                                                                                                                                                                                                               |
| ------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| App in the background (Home), nothing playing                                  | The transfer stopped within ~3 s (9.9 → 16.3 MB) and the download became paused; back in the foreground it resumed from the partial file and completed.                                                                              |
| App in the background, music playing (media foreground service running), run 1 | Continued 35.4 → 72.5 MB, then Android blocked the app's network and expo-network reported it offline; paused. On return the app stayed "offline" (no network event) — fixed by re-reading connectivity when the app becomes active. |
| Same, run 2 (with the fix)                                                     | Continued in the background and completed (61.5 MB → 134 MB within 25 s, MD5 checked).                                                                                                                                               |

So downloads continue in the background only while the process keeps network access (in practice while music plays); otherwise they pause and resume from the partial file when the app is opened again. A download foreground service would be needed for reliable background downloads (not in M2).

### Open issues

- The repository URL in the User-Agent (`https://github.com/anywecon/aulos`) is assumed; change `REPOSITORY_URL` in `app.config.ts` if the public repo gets another name (M4).
- VPN connections: expo-network reports the transport of the active network; a VPN without an underlying Wi-Fi transport counts as metered, so Wi-Fi only may wait under some VPNs.
